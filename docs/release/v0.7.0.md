# v0.7.0 轻量化重构

## 概述

v0.7.0 是架构级轻量化版本：彻底移除 Docker、PostgreSQL、Redis、MinIO、nginx 依赖，整个后端合并为单个 Node 进程，冷启动约 2-3 秒（目标 20 秒内），内存占用大幅下降。

## 主要变更

### 架构

- **数据库**：PostgreSQL → SQLite（Prisma），启动时由内置轻量迁移器自动应用 `prisma/migrations`，不再依赖 Prisma CLI
- **任务队列**：BullMQ + Redis → 进程内队列（并发控制、指数退避重试、启动恢复未完成任务）
- **对象存储**：MinIO → 本地文件系统（默认 `STORAGE_MODE=local`，仍支持 S3 兼容存储）
- **Web 托管**：nginx → API 进程同端口静态托管（`WEB_DIST_DIR` + SPA fallback）
- **Worker**：独立进程/容器 → API 同进程（`TASK_WORKER_ENABLED=true`），SSE 事件改为进程内分发
- **桌面壳**：Docker Compose 编排 → Electron `utilityProcess` 直接拉起内置 Node 服务，端口占用时自动换用随机端口

### v0.6.1 数据迁移

- 首次启动检测旧 Docker 卷（`yunwu-<instance>_postgres_data`）；Docker 可用且本地库为空时自动迁移
- 迁移流程：临时拉起旧 postgres/minio 容器 → 导出用户/会话/消息/任务/资产等全部数据写入 SQLite → 从 MinIO 下载对象到本地存储并改写资产元数据/URL → 清理临时容器
- 旧数据卷保留不动，迁移可重复执行；状态写入 `data/legacy-migration.json`
- Docker 未运行时可稍后在桌面壳状态页手动触发

### 新增：APIXO 上游（默认）

- 新增 APIXO Generation API 上游（`https://api.apixo.ai/api/v1`，文档 https://apixo.ai/docs），并成为默认上游（`PROVIDER_TYPE=apixo`）
- 请求流为异步任务式：`POST /generateTask/{model}` 提交 → 后端内部轮询 `GET /statusTask/{model}?taskId=...`（3 秒间隔，超时可用 `APIXO_POLL_TIMEOUT_MS` 配置，默认 10 分钟）→ 解析 `resultJson.resultUrls` 落盘
- 模型注册表独立：默认启用 `nano-banana`、`nano-banana-pro`、`nano-banana-2`、`gpt-image-1`、`gpt-image-2`、`grok-image`、`flux-2`、`seedream-4-0`，另含 Midjourney、MiniMax、Runway、Seedream 4.5/5.0、Qwen、Wan 等可在管理台按需启用；全部支持文生图 + 图生图
- 图生图参考图：公网 URL 直接透传；本地存储资产自动转 data URL 内联
- `PROVIDER_TYPE=openai-compatible` 可切回 Yunwu 上游，原有行为不变（含用户自带 key、base_url 切换）
- APIXO 模式下管理台 base_url 固定由环境变量控制（PATCH 会返回 400 说明），连通性检查走 `/apikeys/current-balance`

### 新增：三条固定线路 + 按线路隔离的 API key

- 固定三条访问线路：APIXO（默认）、Yunwu、AnyAIGC。线路决定上游适配器、base_url、模型清单与调用格式
- API key 按线路独立保存在 `user_provider_credentials(user_id, provider_route_id)`，一条线路的 key 不会被另一条读到；`user_settings.provider_api_key` 迁移后清空
- 启用模型按线路分别保存（`enabled_model_ids_by_route`），APIXO 与 Yunwu 的模型清单完全不同，来回切换不会互相覆盖
- 模型能力表按线路的 `providerId` 分别登记，`/models`、`/capabilities` 与任务校验都跟随用户当前线路
- 任务创建时记录 `providerRouteId`，Worker 按任务自己的线路取适配器与密钥；切换线路不影响已排队任务
- 新增接口：`PUT/DELETE /api/settings/provider-routes/:routeId/api-key` 与 `POST .../check`

### 新增：端内更新

- 桌面壳发现新版且发布清单带 `sha256` 时，可直接在应用内完成更新：下载 → 校验 → 解压 → 退出后替换程序目录并自动重启
- 下载地址限定本仓库 Release 路径与 portable 资产名；`sha256` 或文件大小不符即丢弃
- 数据目录在 `%APPDATA%/yunwu-desktop`，不在程序目录内，更新不影响数据库与已生成图片
- 安装目录不可写（如放在 `Program Files`）时不显示更新按钮，回退到手动下载

### 打包与发布

- `pnpm desktop:package` 通过 `scripts/prepare-server.mjs` 组装 `resources/server/{api,web}`（pnpm deploy 生产依赖 + Prisma Client + Web 产物）
- `prepare-server.mjs` 会清理 `pnpm deploy` 带进来的本机运行时文件（`data/`、`storage/`、`src/`、`.env`，含 node_modules 里的 workspace 自链接副本），并在发现任何 `.db`/`.env` 残留时直接让打包失败
- Release workflow 移除 GHCR 镜像构建，仅产出 Windows portable zip 与 `yunwu-release.json`
- 移除 `infra/`、`Dockerfile`、compose 脚本与 `docker:*` npm scripts

## 升级说明

- 桌面用户：直接运行 v0.7.0，按提示完成旧数据迁移即可；迁移完成后可自行卸载 Docker Desktop
- 开发者：`pnpm local:prepare` 后直接 `pnpm --filter @yunwu/api dev`，不再需要 `docker:infra:up`
