# v0.7.1 新增 OpenLux 线路

## 概述

v0.7.1 在 v0.7.0 的三条线路（APIXO / Yunwu / AnyAIGC）之外新增第四条访问线路 **OpenLux**，并扩充其 Grok Imagine 模型。线路、密钥、模型清单的隔离机制沿用 v0.7.0 的设计。

## 新增：OpenLux 线路

- 新增线路 `openlux`，地址 `https://api.openlux.ai/v1`，OpenAI Images 兼容（[文档](https://doc.openlux.ai/reference/v1/images/)）
- 端点复用现有适配路径：`POST /v1/images/generations`（JSON）与 `POST /v1/images/edits`（multipart/form-data）
- 独立 `providerId`（`openlux`）。三条 OpenAI 兼容线路的模型清单不同，共用 providerId 会互相覆盖 `model_capabilities` 的启用项与元数据
- 启用模型按线路独立保存，切到 OpenLux 不会带入其他线路的模型，反之亦然
- API key 按线路独立保存；服务端兜底 key 新增 `OPENLUX_API_KEY`，不再让所有 OpenAI 兼容线路共用 `YUNWU_API_KEY`
- `PROVIDER_TYPE=openlux` 可把 OpenLux 设为新用户默认线路

Grok 系列（`grok-3-image`、`grok-imagine-image`、`grok-imagine-image-2.0`、`grok-imagine-image-quality`）按上游要求使用 `aspect_ratio` / `resolution` 参数；界面里的尺寸选项会换算成 `aspect_ratio` 后提交。

模型清单取自 OpenLux 文档中带完整请求示例的条目。该站是中转网关，**实际可用模型取决于账号分组与 token**，权威列表是 `GET /v1/models`（用同一把 key 调用）。

## 升级说明

- 桌面用户：0.7.0 客户端会在启动时检测到新版，点「下载并更新」即可在应用内完成更新
- 已注册用户：在设置页「访问线路」中选择 OpenLux 线路，再在下方密钥页签填入该线路的 key
- 数据库：无 schema 变更，线路以字符串存储在 `user_settings.active_provider_route_id`

## 验证

- API 92 个单测、Web 83 个单测、桌面 3 个单测全部通过
- 新增测试覆盖：OpenLux 端点 URL 与请求体、Grok Imagine 系列的 `aspect_ratio` 换算、线路切换时的模型过滤、线路密钥隔离
- 实测：切到 OpenLux 后 `/models` 只返回该线路模型，建任务成功并记录 `providerRouteId=openlux`，用其他线路的模型会被拒绝
